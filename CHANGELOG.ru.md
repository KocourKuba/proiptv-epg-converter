### Версия 1.6
- Новый параметр `-m, --parallel=[N]`: обработка источников до N рабочими процессами параллельно (по умолчанию: 1 = последовательно). В Linux рабочие процессы создаются через fork (pcntl), в остальных системах запускаются отдельные PHP процессы, поэтому дополнительных расширений не требуется.
- Каждый рабочий процесс пишет собственный временный лог, который по завершении источника добавляется в основной лог одним непрерывным блоком, поэтому сообщения одного источника не перемешиваются с сообщениями другого. После успешной конвертации временный лог удаляется; неудачный источник сохраняет его, а основной лог содержит ссылку на него.

### Версия 1.4
- Для каждого источника создается своя страница (`<target>/<id>/index.html`), переход на нее - по имени источника на информационной странице. На ней перечислены все каналы источника: пикон, EPG id, отображаемые имена, период, который покрывает его телепрограмма, ее глубина и размер его JSON файла.
- Новый параметр `-j, --json-links`: id каждого канала на странице источника становится ссылкой на его JSON файл. По умолчанию выключен, чтобы страница, отдаваемая наружу, не публиковала ссылки на файлы.
- При каждом запуске создается `epg_presets.json` - готовый блок `epg_presets` для ProIPTV со всеми источниками, отдающими телепрограмму. Информационная страница содержит ссылку на его скачивание.
- Новый параметр конфигурации `server_base_url` задает адрес сервера, который записывается в `epg_presets.json` и показывается на информационной странице. Конфигурационный файл теперь может быть объектом с `server_base_url` и `sources`, простой список источников по-прежнему поддерживается.
- Корректно обрабатываются источники, ссылка на которые не содержит расширения файла и молча перенаправляет на настоящий файл. Файл сохраняется под именем, которое отдает сервер (Content-Disposition или последний адрес цепочки перенаправлений), а ETag берется из окончательного ответа, а не из перенаправления.
- Каналы находятся и в том случае, если идентификатор канала не является первым атрибутом тега. Такой источник индексировался вообще без каналов.
- Номер версии хранится в файле `VERSION`

### Версия 1.3
- Новый параметр `-w, --html[=file]`: по окончании работы создается информационная HTML страница. На ней перечислены все источники из конфигурации с их статусом (converted / up to date / failed / not run), количеством каналов, пиконов и передач, периодом, который покрывает телепрограмма, количеством и размером JSON файлов и временем обработки.
- Существенно ускорены индексация источников XMLTV и генерация JSON. Расход памяти больше не растет вместе с размером источника.
- Требуется PHP 8.0 или выше
- Скачивание больших источников больше не прерывается фиксированным таймаутом. Зависшая загрузка определяется по ограничению минимальной скорости.
- При скачивании передается User-Agent, поэтому источники, защищенные фильтром ботов, отдают телепрограмму, а не HTML страницу проверки. Если скачивание не удалось, в лог записывается начало того, что на самом деле отдал сервер.
- Принимаются файлы XMLTV, начинающиеся с UTF-8 BOM или без XML декларации
- Каналы, id которых содержит XML сущность (например `A&amp;E`), больше не остаются без EPG
- В Windows JSON файлы каналов, id которых содержит символы вроде `\` или `:`, удалялись как устаревшие при каждом запуске
- Каждый источник записывает `channels_info.json` со списком своих EPG id и псевдонимов каналов
- В создаваемом JSON категория передачи сохраняется как `main_category`, дата - как `year`, а изображения передачи добавляются как `icons`
- Новый параметр `-f, --force`: обрабатывать источники, даже если они актуальны
- Новый параметр `-p, --purge`: принудительная очистка устаревших файлов
- Параметр уровня лога переименован из `-d, --debug` в `-s, --severity`
- Исправлен параметр `--target`, который игнорировал свое значение
- Неудачное скачивание учитывается как ошибка
- Каталоги создаются с правами 0775
- Ошибки разбора XML записываются в лог со строкой и позицией ошибки
- Ускорена запись лога
